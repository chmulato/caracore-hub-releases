Como o Hub roda

Tecnologia

Java 25 e Jakarta EE 10 sobre um Tomcat que já vai dentro do instalador, com SQLite no computador do ponto. Sem servidor de banco para contratar e sem nuvem obrigatória.

A pilha

Aplicação

Java 25 e Jakarta EE 10, em módulos separados de núcleo, persistência, API e interface. A interface é JSP e a API é REST (JAX-RS/Jersey), usada pelas telas e pelas integrações.

Servidor

Apache Tomcat 10.1 embutido no instalador Windows. Não é preciso instalar servidor nem configurar porta: o programa sobe o Tomcat local e abre a interface.

Banco de dados

SQLite local em modo WAL, no computador do ponto. O arquivo do banco fica na pasta do Hub, e a própria aplicação faz a cópia de segurança dele.

Pacote

Electron inicia o Tomcat e abre a janela do Hub. Dentro do pacote vão o Java 25 e o Tomcat: o computador do ponto não precisa de JDK instalado.

Perfis e permissões

Três perfis nas telas e nas rotas administrativas: ADMIN, SUPERVISOR e OPERADOR.

ADMIN

Configuração, usuários, auditoria e logs. As rotas de administração respondem 200 para o ADMIN.

SUPERVISOR

Operação do ponto com supervisão da equipe. Nas rotas de administração, a resposta é 403.

OPERADOR

Recebimento, guarda, busca na lista e retirada no balcão. Também recebe 403 nas rotas de administração.

A recusa por perfil sai em JSON, com mensagem de erro padronizada, e não como página HTML do servidor. A auditoria de usuários fica gravada em tabela própria e é lida em Administração → Auditoria e Logs.

De onde vêm as encomendas

Três conectores nesta edição, cada um com API e webhook: Mercado Livre, Shopee e Temu. Além deles, o balcão pode cadastrar qualquer encomenda manualmente.

Amazon e B2W não têm conector nesta edição: existem apenas no modelo de dados e não aparecem no filtro de canais.

As notificações por WhatsApp dependem de configuração. O cache em Redis é opcional: o pacote Windows funciona sem um servidor Redis, e o estado do ponto fica no SQLite local.

O que fica de fora

Para não confundir o que é produto com o que é etapa de build.

O WAR é artefato interno

Durante o build, a aplicação é empacotada como WAR e embutida no instalador e no ZIP. O WAR não é distribuído como produto: quem instala o Hub não lida com ele.

Sem nuvem obrigatória

A operação do ponto funciona com o banco local. Não é preciso contratar servidor de banco, container ou hospedagem para usar o Hub.

Sem aplicativo móvel

O Hub roda no computador do ponto. Não existe app para celular nesta edição.

Sem versão para Mac ou Linux

A pré-release v2.1.0-rc1.7 é Windows x64. Mac e Linux não entram nesta versão.
