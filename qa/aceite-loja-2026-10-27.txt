3. WHAT THIS ROUND CHANGED
   a) Font/CLS: docs/assets/css/portal-style.css gained a metric-compatible
      @font-face ('Inter Fallback', Arial, size-adjust:107% with ascent/descent/
      line-gap overrides) and body now uses 'Inter','Inter Fallback',... ; the
      four pages changed Google Fonts display=swap -> display=optional.
      Effect: swap period no longer shifts text (see section 5).
   b) A11y: 5 inline links in download.html got underline (a11y 95 -> 100).
   c) Copy correction in download.html (the "still does not do" list): the item
      used to say "A retirada ainda não confere cada volume, um a um". That was
      factually wrong — the packaged app DOES confer per volume:
        - web/src/main/webapp/retirada/retirar.jsp:183-186 — one checkbox per
          volume, name="volumeId", disabled unless the volume is PRONTO;
        - web/.../servlet/RetiradaServlet.java:72-86 — the checked ids are posted
          to PedidoService.registrarRetirada(pedidoId, volumesConferidos, user);
        - persistence/.../PedidoService.java:107-117 — the order only closes when
          every pending volume was conferred;
        - api/.../PedidoResource.java:277 — POST /api/pedidos/{id}/retirada/conferencia
          (and /{id}/retirada/scan -> registrarRetiradaVolume at :239-255).
      New text (download.html:136): "A leitura por leitor de código de barras não
      foi testada com equipamento nesta pré-release. A conferência pela tela é por
      volume: cada volume tem a sua caixa e o pedido só fecha quando todos forem
      marcados." — it states the limitation (no hardware test) without denying the
      capability and without claiming acceptance that was never run.
   d) Removed docs/_dbg_download.html (debug copy that Pages would have served).

   underline fix (download was 95 before it). CLS ends at 0 on all four; the only
   layout shift left before the font fix was the Inter swap (0.057 / 0.082 / 0.100
   in consecutive runs, i.e. the same defect measured with run-to-run noise), and
   it disappears once the metric-compatible fallback is in place. Performance
   figures are pessimistic by construction: python -m http.server serves without
   gzip and without cache headers, so uses-text-compression, uses-long-cache-ttl
   and cache-insight are red no matter what the page does; GitHub Pages gzips and
   caches the same static files. What remains real and out of this round's scope:
   render-blocking Tailwind CDN + Font Awesome CDN, and image-delivery on the
   full-size screenshots (portal-wide decision).

   Note on timing: the Lighthouse runs above predate the copy correction of 3.c
   (text-only swap inside one <li>), which therefore has no font, image or layout
   effect; the markup/anchor/link/responsiveness battery was re-run on the final
   text (section 4).

8. WHAT THIS ROUND DID NOT TEST (do not read as approved)
   - The pages were served locally (python -m http.server 8099, 127.0.0.1), not
     from GitHub Pages; the deployed headers (gzip, cache) were not measured.
   - Lighthouse ran on Edge/Chromium mobile emulation only; no Firefox or Safari.
   - No screen-reader pass, no axe/pa11y run beyond what Lighthouse covers.
   - The three screenshots are the product's own captures; they were checked for
     dimensions and format, not re-verified against the rc1.7 runtime.
   - Nothing here homologates the product: the Hub stays a Pre-release, not
     homologated, GA 06/04/2027.

9. HOW TO REPRODUCE
   start the local server:
     python -m http.server 8099 --bind 127.0.0.1 --directory D:\onedrive\dev\caracore-hub-releases\docs
   battery (outputs in D:\temp\hub-loja-qa-20261027):
     python aceite_loja.py      -> aceite-r3.out
     python validate_loja.py    -> valid-r3.out
     python anchors.py          -> anchors-r3.out
     python inbound2.py         -> inbound-r3.out
     python amz.py              -> amz-r3.out
     python tagcheck.py         -> tags-r3.out
     python imgsize.py          -> imgsize-r3.out
     python resp.py             -> resp-r3.out (Playwright/Edge, 7 widths)
     python linkcheck.py        -> link-r3.out (stdout) + linkcheck.out (per URL)
   lighthouse (per page):
     npx -y lighthouse@12 http://127.0.0.1:8099/download.html --output=json \
       --output-path=lh3-download.json --chrome-flags="--headless=new" --only-categories=performance,accessibility,best-practices,seo
     python lhsum.py            -> lhsum4.out (reads lh*.json)
